# Wan 3.0 视频提示词写作指南

本指南由 bestimage.ai 团队整理与维护，用于把一个模糊创意变成可执行、可迭代的视频生成指令。它不绑定某个第三方界面的固定参数，适合文生视频、图生视频、参考生视频、首尾帧和视频编辑工作流。

## 1. 先写事件，再写美术

视频模型首先需要理解“什么在变化”。比起先堆砌摄影术语，更稳定的顺序是：

```text
谁 + 在哪里 + 为什么开始动作 + 动作如何连续发生 + 最终停在哪里
```

例如，不要只写“电影感咖啡广告、浅景深、粒子、慢动作”。可以写：

```text
咖啡豆从麻布袋口滚出，沿木桌弹跳两次后落入手摇磨豆机；摇柄开始转动，细粉从下方抽屉缓慢堆起，最后一缕蒸汽把画面自然遮住。
```

动作链明确后，再补充镜头、光线、声音和色彩。

## 2. Wan 提示词的八层结构

### 输出层

说明时长、画幅和整体媒介，并在界面或 API 同步设置支持的参数。提示词不能启用平台未支持的参数；遇到不支持的要求应先确认工作流，不要自行换模型。

```text
10 秒，9:16，写实手机纪录片质感。
```

### 身份层

为人物或产品保留少量、可复述的锚点。一个人物推荐 3–5 项：年龄段、脸部特征、发型、主服装、标志配件。

```text
短卷发、左眉有浅痣、砖红色工装夹克、银色圆框眼镜的年轻修表师。
```

后续镜头原样重复这些锚点，不要改写为大量近义词。

### 世界层

定义地点、时间、天气和前中后景。空间关系越清晰，穿帮越少。

```text
清晨的窄小修表铺，前景是散落齿轮，中景为木质工作台，后景窗外有缓慢经过的电车。
```

### 动作层

使用因果与反馈：

```text
先夹起发条 → 发条释放并回弹 → 他用拇指稳住齿轮 → 秒针重新走动。
```

描述可见的物理结果，而非抽象词“充满动感”。

### 摄影机层

每个镜头只给一个主要运动：推、拉、横移、环绕、升降、手持跟随、静止。复杂路径拆成时间段。

```text
0–3 秒：静止微距；3–7 秒：沿桌面缓慢横移；7–10 秒：轻轻抬升到人物眼睛。
```

### 视觉层

写主光方向、色温、对比度、材质和景深。避免互相冲突的风格标签。

```text
窗外冷色散射光作为主光，台灯形成暖色局部光池；金属划痕和指纹真实，背景柔和虚化。
```

### 声音层

如果入口支持音频，按优先级写：对白 > 关键动作音 > 环境音 > 配乐。

```text
声音：齿轮轻响清晰，远处电车经过，人物低声说“走起来了”；无音乐，无字幕。
```

### 约束层

只写与场景高度相关的约束：

```text
保持眼镜、夹克和工作台位置一致；工具只出现一套；手指数量自然；不要时间跳跃、字幕或品牌标志。
```

## 3. 不同输入模式

### 文生视频 T2V

T2V 需要完整世界信息。建议先用 6–8 秒验证角色和场景，再扩展为多镜头版本。若同一提示里出现两个地点，明确使用什么转场以及人物如何到达。

### 图生视频 I2V

首图定义构图和外观，提示词重点应转为运动。注意：本库记录的 bestimage.ai 图生视频入口还要求尾图；先准备与动作终点一致的尾帧，不能把下列运动描述当作只需一张图的接口示例：

```text
保持首图人物、服装、背景建筑和构图不变。人物先眨眼一次，再被左侧微风吹动两缕发丝，右手缓慢抬起遮住阳光。摄影机仅向前推进 8%，不要环绕；背景只有树叶轻微摆动。
```

使用“幅度”能减少过度运动：轻微、半步、旋转 30 度、推进 8%、停顿 0.5 秒。

### 首尾帧

不要只描述两个状态，要补全合理过程：

```text
从空桌首帧到完成早餐的尾帧：托盘由画面右侧被一双手平稳推入，杯子先放下，面包盘随后放下，手最后把餐巾展开并离开画面。桌面、窗光和摄影机保持不变。
```

### 参考生视频 R2V

对每份输入分配单一职责：

```text
图片 1：人物身份与服装；图片 2：咖啡店空间与色调；视频 1：调酒动作节奏，仅参考动作，不复制人物；音频 1：剪辑节拍。生成全新的剧情和镜头。
```

如果身份、动作、场景都从同一参考中提取，模型更容易混淆。职责拆分有利于一致性。

### 视频编辑

使用“只改 X，保持 Y”结构：

```text
仅把天气从晴天改为初雪。保持原视频人物身份、步伐、镜头运动、建筑、车辆位置、时长和剪辑点不变。积雪只在静止表面积累，不遮挡人物脸部。
```

## 4. 多镜头叙事

多镜头不是多个独立画面的拼贴。每个镜头应向同一目标推进：

```text
0–3 秒：建立地点与目标。
3–7 秒：动作产生阻力或意外。
7–11 秒：人物做出选择。
11–15 秒：用可见结果收束。
```

跨镜头重复角色锚点，并声明左右关系：

```text
红夹克人物始终在蓝外套人物左侧；对话反打镜头也保持视线方向连续。
```

转场可使用遮挡物、动作匹配、光线闪变或声音桥。短片里使用一次自然转场通常比连续炫技更稳定。

## 5. 人物与商品一致性

### 人物锁定块

```text
身份锁定：32 岁女性，椭圆脸，短黑卷发，左眉浅痣，砖红色夹克，银色圆框眼镜。所有镜头保持同一张脸、同一发型、同一服装、同一身高比例。
```

### 商品锁定块

```text
产品锁定：矮方形透明玻璃瓶、圆角肩部、哑光银盖、正面无字矩形标签区。所有角度保持尺寸、瓶盖、液面高度、标签位置和玻璃颜色一致。
```

产品运动越复杂，越需要减少背景特效。先验证产品结构，再增加液体、粒子或机械展开。

## 6. 多语言与对白

视觉描述可以使用一种主语言，对白单独保留原文：

```text
画面描述使用中文。
对白语言：日语，东京标准口音，轻声，语速自然。
女店员说：“雨、まだ止みそうにないですね。”
男顾客停顿 0.4 秒后回答：“もう少し、ここにいます。”
没有字幕。说话者口型自然；倾听者闭嘴，只做一次轻微点头。
```

英文制作术语可嵌入中文描述，但不要把整段提示机械翻译两遍。若需要画面文字，使用“精确文字”字段并保持短小；复杂排版建议后期完成。

## 7. 声音设计

声音应服务画面因果：门关上才出现碰撞声，脚落地才出现脚步声。提示音量层级：

```text
前景：刀切脆皮的细响；中景：油锅轻微滋滋声；远景：餐厅交谈模糊低沉；无配乐。
```

对白场景减少背景音乐，MV 场景则让剪辑点、动作重拍和音乐小节对齐。不要在十秒内塞入过长台词。

## 8. 负面约束

有效的负面约束与镜头相关：

- 人物：无换脸、无额外手指、无服装漂移。
- 商品：无标签变形、无瓶盖消失、无液体穿透玻璃。
- 汽车：轮胎持续接地、车身不拉伸、反射跟随透视。
- 多镜头：无角色左右互换、无突然换景、无时间倒流。
- 通用：无水印、无字幕、无品牌标志（除非明确需要且拥有权利）。

超长的通用负面词表可能稀释重点。每次选择 3–6 个最相关问题即可。

## 9. 迭代方法

1. 基础版只保留一个主体、一个动作、一个镜头运动。
2. 固定满意的角色或首帧。
3. 第二版只增加环境反馈或声音。
4. 第三版再加入转场、多镜头或特效。
5. 保留各次结果与输入，记录每次只改变的变量；不要覆盖已经确认的版本。固定 seed 有助于记录，但不能保证跨模型版本重现相同画面。

## 10. 发布前检查

- 三秒内能否看懂主体与目标？
- 动作是否有起因、过程和结果？
- 镜头运动是否互相冲突？
- 角色或产品锚点是否在每段保持一致？
- 台词是否能在时长内自然说完？
- 有没有不必要的品牌、受保护角色或未授权肖像？
- 画面文字是否确实必须由模型生成？

通过以上检查后，再提高分辨率或制作正式版本。

## 11. 输入准备与输出检查

- [148 条提示词](../prompts/README.md)均明确模式、时长、画幅、声音、输入角色、可调项与检查目标，便于选择场景并逐项检查输出。
- `I2V` 在本平台需要首尾两图；`R2V` 的参考片段需要分别检查视频与音频总时长；`Video Edit` 需要检查原片与输出时长之和。详见[能力说明](model-capabilities.md)及[英文 API 指南](bestimage-wan-3-api.md)。
- 不将“精准口型”“像素保持”“手语正确”等要求写成已实现功能。具体结果需要逐帧或听审，专业内容还要由对应人员检查。
- [GPT Image 2 图像工作流](bestimage-wan-3-api.md#gpt-image-2-reference-frame-workflow)可用于先准备角色或产品参考帧，但本库没有实现自动调用链。
- 本库[静态概念图](../assets/README.md)与视频条目对应，只说明构图意图，不能证明时间连续性或模型表现。
- [15 语种入口](../locales/README.md)各包含完整对照例子，前六类核心提示词为中文、后八类为英文，不能将入口语言数量当作全库翻译数量。
