# Wan 视频生成故障排查

由 bestimage.ai 团队整理。以下是排查假设，不是对未查看结果的确定诊断。先记录真实输入、平台、请求字段和输出证据，再逐项比较。

## 人物在不同镜头变脸

**可能的原因**：身份描述太多、每段改写称呼、镜头角度跨度过大，或同时要求换装。

**修复**：把 3–5 个身份锚点复制到每个镜头；先取消换装；从正面到侧面之间增加过渡角度；有参考图时明确“图片 1 仅用于人物身份”。

## 图生视频动作过大

**可能的原因**：只写“动起来、充满活力”，模型自行增加全身和摄影机运动。

**修复**：指定动作部位与幅度，例如“只抬起右手至胸口”“摄影机仅推进 5%”“背景人物保持静止”。

## 产品瓶身或标签变形

**可能的原因**：复杂环绕、液体特效和产品旋转同时发生。

**修复**：先固定产品正面并只移动摄影机；加入商品锁定块；把液体特效放到第二次迭代；需要精确文字时后期合成标签。

## 动作像瞬移

**可能的原因**：提示只写开始与结果，没有中间过程。

**修复**：增加两到三个连续动作节点和环境反馈，例如“屈膝—蹬地—离地—落地时灰尘扩散”。

## 运镜混乱或眩晕

**可能的原因**：同一时间要求推近、环绕、摇镜、变焦和手持。

**修复**：每个镜头保留一个主要运动。需要组合时分段，并用静止半秒作为连接。

## 左右位置反转

**可能的原因**：反打镜头没有注明轴线与视线关系。

**修复**：声明“角色 A 始终位于角色 B 的画面左侧，摄影机不越过两人连线”。

## 对白口型错误

**可能的原因**：句子太长、多人同时说话、语速和停顿不明确。

**修复**：缩短对白；一次只让一人说话；注明非说话者闭嘴；标记语言、口音、情绪和 0.3–0.6 秒停顿。

## 画面出现乱码文字

**可能的原因**：环境中包含招牌、包装或屏幕，模型尝试自动补字。

**修复**：明确“所有招牌为空白或抽象图形”；把准确文字留到后期；若必须生成，只保留一个短词并写成精确文字。

## 风格很好但故事不清楚

**可能的原因**：美术词过多，事件目标不明确。

**修复**：将提示第一段改成一句可见事件：“人物为了拿到 X，必须完成 Y，最终产生 Z。”其余风格信息放后面。

## 速度感变成物体拉伸

**可能的原因**：用“极快、爆炸速度”代替物理线索。

**修复**：使用背景视差、轮胎排水、衣物风压、固定快门拖影和声音变化来表现速度，并声明主体几何不变。

## 多镜头像随机拼接

**可能的原因**：每段地点、人物、光线或时间都不同。

**修复**：共享同一角色锚点和色彩基调；下一镜头从上一镜头的动作结果开始；使用动作匹配、遮挡转场或声音桥。

## 一份简洁的重试模板

```text
重试上一版本，仅修复：{一个问题}。
必须保持：{人物/商品身份、场景、构图、动作、时长中的不变项}。
具体调整：{可测量的幅度或单一镜头修改}。
不要新增人物、道具、对白、转场或特效。
```

## 请求还未生成就被拒绝

先保存错误码、请求 ID 和不含凭据的字段摘要，区分参数校验、账户权限、限流与网络失败。不要据此认定是模型能力问题。

- I2V 检查首图和尾图是否都提交，图片尺寸、格式与透明通道是否符合要求。
- R2V 检查图片数量，单片时长，以及视频总时长、音频总时长是否分别超限；不要只检查单片。
- Video Edit 检查原片时长与输出时长相加是否超过文档限制。
- `files` 与 `links` 不要同时提交，网页是否公开可访问还与服务地区有关。
- 不把阿里云原生字段或 GPT Image 2 图像字段直接放进 bestimage.ai Wan 请求体。

完整字段见[API 指南](bestimage-wan-3-api.md)。bestimage.ai API 使用 `https://api.flaq.ai`，请使用在 bestimage.ai 账户中获取的 API 密钥。

## 提交超时或轮询很慢

网络超时不证明任务未创建。先查账户任务历史、保存已有 task ID，不自动再次提交。轮询遇到未知状态、失败、限流或异常响应时保留证据并停止；客户端等待期限到达也不等于服务端任务已取消。示例中的有限轮询不包含自动取消或自动重试提交。

## 静态概念图好看，视频却不稳定

静态图没有验证动作、声音或时间一致性。按[条目的检查项](../prompts/README.md)检查实际视频，减少一次尝试中的变量，但不要把未确认的其他模型或模式当作替代结果。图片的真实生成来源见[素材记录](../assets/README.md)。
